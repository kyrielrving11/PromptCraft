# 后退提示 Skill

## 示例1：科学原则题

### 用户任务及输出格式

任务：回答一道涉及物理原则的选择题。

输出格式：先展示后退问题和抽象依据，再输出最终选项和一句理由。

### 生成的后退提示 Prompt

```
你是一名擅长抽象物理原则并进行稳健推理的科学问答助手。

请使用 Step-Back Prompting 处理任务：先不要直接回答原始问题，而是先后退一步，抽象出更高层的概念、原则、通用问题或背景事实；再基于这些抽象内容回到原始问题，完成稳健推理并给出最终答案。

### 原始任务
回答下面的物理选择题。

### 待处理内容
"""
{用户输入的物理题}
"""

### 可选参考案例
未检测到用户案例，因此按零样本后退提示生成；请自行生成后退问题和抽象依据。

### 输出要求
- 输出“后退问题”。
- 输出“抽象依据”。
- 输出“最终答案：<选项>”。
- 用一句话说明理由。

### 约束条件
- 检查公式适用条件和单位。
- 不要添加无关解释。

### 执行方法
1. Abstraction：从原始问题中识别最关键的具体细节、领域和约束。
2. Step-back question：提出一个更高层、更通用、但仍覆盖原题所需信息的后退问题。
3. Abstract answer：回答后退问题，提取相关概念、原则、公式、背景事实、判断标准或通用框架。
4. Abstraction-grounded reasoning：基于抽象依据回到原始问题，逐项应用到具体条件上。
5. Check：确认最终答案没有丢失原始问题中的时间、对象、条件、单位、格式或证据要求。
6. 输出控制：展示后退问题、抽象依据和简明推理摘要。

如果输出要求指定了严格格式，请优先满足该格式。
```

### 解释

- 后退动作：从具体题目后退到物理概念、公式或守恒关系。
- 抽象依据：先稳定原则，再回到题目数字和条件。
- 与思维链区别：重点不是多写步骤，而是先找高层原则来减少中间错误。

## 示例2：时间约束知识问答

### 用户任务及输出格式

任务：回答某人在特定时间范围内所在机构、职位或身份。

输出格式：只输出简短答案和证据摘要。

### 生成的后退提示 Prompt

```
你是一名擅长时间线归纳和知识问答的研究助手。

请使用 Step-Back Prompting 处理任务：先不要直接回答原始问题，而是先后退一步，抽象出更高层的概念、原则、通用问题或背景事实；再基于这些抽象内容回到原始问题，完成稳健推理并给出最终答案。

### 原始任务
根据人物时间线回答特定时间范围内的机构、职位或身份。

### 待处理内容
"""
{用户输入的问题和上下文}
"""

### 可选参考案例
未检测到用户案例，因此按零样本后退提示生成；请自行生成后退问题和抽象依据。

### 输出要求
- 答案：<简短答案>
- 证据摘要：<1-2 句>
- 如果证据不足，输出“证据不足”。

### 约束条件
- 后退问题应关注人物的完整教育、职业或任职历史。
- 最终答案必须匹配原始问题中的时间范围。
- 不要编造上下文没有的信息。

### 执行方法
1. Abstraction：从原始问题中识别最关键的具体细节、领域和约束。
2. Step-back question：提出一个更高层、更通用、但仍覆盖原题所需信息的后退问题。
3. Abstract answer：回答后退问题，提取相关概念、原则、公式、背景事实、判断标准或通用框架。
4. Abstraction-grounded reasoning：基于抽象依据回到原始问题，逐项应用到具体条件上。
5. Check：确认最终答案没有丢失原始问题中的时间、对象、条件、单位、格式或证据要求。
6. 输出控制：展示后退问题、抽象依据和简明推理摘要。

如果输出要求指定了严格格式，请优先满足该格式。
```

### 解释

- 后退动作：从“某个时间点/时间段问什么”后退到“完整历史是什么”。
- 抽象依据：完整时间线比孤立时间点更容易支持准确判断。
- 防错关键：最后必须回到原始时间范围，不要只回答后退问题。

## 示例3：严格 JSON 风险抽取

### 用户任务及输出格式

任务：从合同条款中抽取风险、原则依据和建议动作。

输出格式：只输出 JSON，不展示后退过程。

### 生成的后退提示 Prompt

```
你是一名严谨的合同风险分析助手。

请使用 Step-Back Prompting 处理任务：先不要直接回答原始问题，而是先后退一步，抽象出更高层的概念、原则、通用问题或背景事实；再基于这些抽象内容回到原始问题，完成稳健推理并给出最终答案。

从合同条款中抽取风险、原则依据和建议动作。

### 待处理内容
"""
{用户输入的合同条款}
"""

### 可选参考案例
未检测到用户案例，因此按零样本后退提示生成；请自行生成后退问题和抽象依据。

### 输出要求
只输出 JSON 数组。每个对象包含：
- risk

- evidence 必须来自原文。

1. Abstraction：从原始问题中识别最关键的具体细节、领域和约束。
2. Step-back question：提出一个更高层、更通用、但仍覆盖原题所需信息的后退问题。

5. Check：确认最终答案没有丢失原始问题中的时间、对象、条件、单位、格式或证据要求。
6. 输出控制：在内部完成后退问题、抽象依据和推理摘要，最终只输出指定 JSON。

如果输出要求指定了严格格式，请优先满足该格式。
```

### 解释

- 后退动作：从具体条款后退到合同风险判断原则。
- 抽象依据：先确定风险类型和判断标准，再回到原文证据。
- 严格输出：后退过程作为内部工作，最终只输出 JSON。
