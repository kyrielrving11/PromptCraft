# 少样本思维链案例

## 生成 Prompt 的原则

1. 角色扮演，在提示开头明确模型的角色和任务意图。

   示例：

   ```
   你是一名严谨的数学解题助手，负责按照示例中的推理步骤解决应用题。
   ```

2. 使用明确指令，将任务目标放在提示前部，并使用 `###`、三引号 `"""` 或代码块分隔指令、示例和待处理问题。

3. 用户提供完整推理案例时，插入 1~5 组少样本思维链示例。每个示例必须包含问题/输入、推理过程和最终答案。

4. 推理过程必须出现在最终答案之前。少样本思维链依赖“先分解问题，再给答案”的顺序。

5. 推理过程应使用自然语言表达关键中间步骤，而不是只给公式、只给最终答案或只增加无意义占位符。

6. 输出格式要明确区分推理过程和最终答案。例如：

   ```markdown
   推理过程：
   ...

   最终答案：
   ...
   ```

7. 示例应来自用户在首次请求中附上的相关问题，不要把 `sample.md` 中的案例直接混入用户 Prompt。

8. 对代码、数学、日期、状态追踪、符号操作等任务，推理步骤要展示变量变化、计算过程或判断依据。

## 与零样本思维链的区别

- 零样本思维链通常在 Prompt 末尾加入“Let’s work this out in a step by step way to be sure we have the right answer.”，但不提供推理示例。
- 少样本思维链会提供 1~5 组完整示例，让模型学习“如何推理”和“如何输出答案”。
- 当用户没有提供完整推理案例时，本 skill 自动退回零样本思维链，并在示例区说明原因。

## 与少样本提示的区别

- 少样本提示使用 `输入 -> 输出` 示例。
- 少样本思维链使用 `输入 -> 推理过程 -> 输出` 示例。
- 如果任务只需要格式模仿，用少样本提示；如果任务需要多步推理、状态追踪、计算或隐含常识判断，用少样本思维链。

## 示例块格式

```markdown
#### 示例 1
问题：
"""
用户提供的相关问题
"""

推理过程：
"""
用户提供的分步推理过程
"""

最终答案：
"""
用户提供的最终答案
"""
```

## 逐步生成方法

1. 读取任务描述、目标问题、输出格式和可选用户示例。
2. 判断任务是否需要多步推理；如果只是格式迁移，可建议使用少样本提示。
3. 提炼角色和任务目标。
4. 有完整用户示例时，将示例格式化为问题、推理过程、最终答案三段。
5. 没有完整用户推理案例时，在示例区说明按零样本思维链生成，不要编造示例。
6. 写清输出格式、答案位置、语言、字段和禁止项。
7. 使用三引号包裹待处理问题或占位符。
8. 输出完整 Prompt。

## 常见 Gotchas

- 示例只有问题和答案、没有推理过程时，不符合少样本思维链要求；不要编造推理案例，可按零样本思维链生成。
- 推理过程放在答案之后会削弱 CoT 引导效果，应保持先推理后答案。
- 示例和目标问题类型不一致时，模型会学习错误的推理模式。
- 推理步骤过长会挤占上下文，应保留关键步骤，删除闲聊式解释。
- 最终答案没有单独标记时，模型可能输出难以解析的长段文本。
