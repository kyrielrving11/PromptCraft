# 最少到最多提示 Skill

## 示例1：多步骤数学题

### 用户任务及输出格式

任务：解决一道多步骤数学应用题。

输出格式：展示问题拆解、每个子问题答案，最后单独输出最终答案。

### 生成的最少到最多提示 Prompt

```
你是一名严谨的数学推理助手。

请使用 Least-to-Most Prompting 解决任务：先把原始问题拆成有序子问题，再按顺序解答子问题，并用前面子问题的答案帮助回答后续子问题，直到得到最终答案。

### 原始任务
解决下面的数学应用题。

### 待处理内容
"""
{用户输入的数学题}
"""

### 输出要求
- 先输出“问题拆解”。
- 再输出“子问题有序解答”。
- 最后输出“最终答案：<答案>”。
- 检查算术和单位。

### 约束条件
- 不要跳步。
- 不要添加与题目无关的解释。

### 执行方法
1. Problem Reducing：自上而下拆解原始问题，列出必要且有依赖顺序的子问题。
2. 子问题排序：从最基础、最容易验证的子问题开始，逐步过渡到更综合的子问题；最后一个子问题必须直接导向原始问题的最终答案。
3. Sequentially Solve Subquestions：自下而上依次回答子问题。回答第 N 个子问题时，只使用原始题目、约束条件以及第 1 到 N-1 个子问题的答案作为上下文。
4. 一致性检查：确认所有子问题答案共同支持最终答案，且最终答案符合输出要求。
5. 输出控制：展示问题拆解和子问题答案。

### 建议输出结构
如果允许展示过程，使用：

#### 问题拆解
1. ...
2. ...

#### 子问题有序解答
1. 子问题：...
   答案：...
2. 子问题：...
   答案：...

#### 最终答案
...

如果输出要求指定了严格格式，请优先满足该格式。
```

### 解释

- 零样本特征：没有用户输入/输出示例。
- Least-to-Most 特征：先拆解，再按顺序解答，后续答案依赖前序答案。
- 输出可解释：展示子问题和答案，而不是要求模型输出隐藏思维链。

## 示例2：长文分析

### 用户任务及输出格式

任务：从长文中提炼核心观点、证据链和结论。

输出格式：Markdown 表格，字段为“子问题、答案、证据位置、对最终结论的作用”，最后输出 3 条结论。

### 生成的最少到最多提示 Prompt

```
你是一名擅长长文结构化分析的研究助手。

请使用 Least-to-Most Prompting 解决任务：先把原始问题拆成有序子问题，再按顺序解答子问题，并用前面子问题的答案帮助回答后续子问题，直到得到最终答案。

### 原始任务
分析下面长文的核心观点、证据链和最终结论。

### 待处理内容
"""
{用户输入的长文}
"""

### 输出要求
- 使用 Markdown 表格。
- 表格字段为：子问题、答案、证据位置、对最终结论的作用。
- 表格后输出 3 条最终结论。
- 输出语言为中文。

### 约束条件
- 不要编造原文没有的信息。
- 证据位置可以用段落、标题或原文关键词标识。
- 如果证据不足，明确写“证据不足”。

### 执行方法
1. Problem Reducing：自上而下拆解原始问题，列出必要且有依赖顺序的子问题。
2. 子问题排序：从最基础、最容易验证的子问题开始，逐步过渡到更综合的子问题；最后一个子问题必须直接导向原始问题的最终答案。
3. Sequentially Solve Subquestions：自下而上依次回答子问题。回答第 N 个子问题时，只使用原始题目、约束条件以及第 1 到 N-1 个子问题的答案作为上下文。
4. 一致性检查：确认所有子问题答案共同支持最终答案，且最终答案符合输出要求。
5. 输出控制：展示问题拆解和子问题答案。

如果输出要求指定了严格格式，请优先满足该格式。
```

### 解释

- 适用场景：长文分析天然需要先识别局部事实，再组合成整体结论。
- 子问题递进：事实抽取 -> 证据判断 -> 观点归纳 -> 结论整合。
- 格式稳定：最终输出由表格和 3 条结论组成。

## 示例3：只输出最终 JSON 的复杂抽取

### 用户任务及输出格式

任务：从合同条款中抽取风险项、责任方、触发条件和建议动作。

输出格式：只输出 JSON 数组，不展示推理过程。

### 生成的最少到最多提示 Prompt

```
你是一名严谨的合同风险抽取助手。

请使用 Least-to-Most Prompting 解决任务：先把原始问题拆成有序子问题，再按顺序解答子问题，并用前面子问题的答案帮助回答后续子问题，直到得到最终答案。

### 原始任务
从合同条款中抽取风险项、责任方、触发条件和建议动作。

### 待处理内容
"""
{用户输入的合同条款}
"""

### 输出要求
只输出 JSON 数组。每个对象包含：
- risk_item
- responsible_party
- trigger_condition
- suggested_action
- evidence

### 约束条件
- 不要输出 Markdown 代码块。
- 不要输出解释性文字。
- 字段缺失时使用 null。
- evidence 必须来自原文。

### 执行方法
1. Problem Reducing：自上而下拆解原始问题，列出必要且有依赖顺序的子问题。
2. 子问题排序：从最基础、最容易验证的子问题开始，逐步过渡到更综合的子问题；最后一个子问题必须直接导向原始问题的最终答案。
3. Sequentially Solve Subquestions：自下而上依次回答子问题。回答第 N 个子问题时，只使用原始题目、约束条件以及第 1 到 N-1 个子问题的答案作为上下文。
4. 一致性检查：确认所有子问题答案共同支持最终答案，且最终答案符合输出要求。
5. 输出控制：在内部完成问题拆解和子问题解答，最终只输出指定 JSON。

如果输出要求指定了严格格式，请优先满足该格式。
```

### 解释

- Least-to-Most 仍然存在，但过程被设为内部工作。
- 适合严格结构化输出：最终只给 JSON，便于程序解析。
- 风险抽取依赖顺序：先识别条款事实，再判断风险，再映射责任方和动作。
