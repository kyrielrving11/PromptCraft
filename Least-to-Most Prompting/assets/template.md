# 最少到最多提示模板

## 论文机制提炼

Least-to-Most Prompting 的关键流程：

1. 先把复杂问题拆成一组更简单的子问题。
2. 子问题要有顺序，后面的子问题能使用前面子问题的答案。
3. 原始问题应作为最后目标被回答。
4. 解答时逐个推进：当前上下文 = 原始问题 + 已回答子问题 + 当前子问题。
5. 对普通使用场景，可以把“拆解”和“解答”合并到单轮 Prompt；对脚本或外部流程，可以拆成两次或多次模型调用。

## 生成 Prompt 的原则

1. 在角色中强调“复杂问题拆解”和“顺序求解”。
2. 不要求用户提供示例；用任务说明、输出格式和约束生成零样本 Least-to-Most Prompt。
3. 拆解阶段只产出子问题，不提前给答案。
4. 子问题从简单到复杂排列，最后一个子问题直接回答原始问题。
5. 解答阶段逐一回答子问题，并显式引用前面已经得到的答案。
6. 如果用户要求最终只输出指定格式，让模型把拆解和中间答案作为内部工作，不展示过程。
7. 如果用户要求过程可见，输出“问题拆解 / 子问题有序解答 / 最终答案”。

## 逐步生成方法

1. 读取任务、待处理内容、输出格式和约束。
2. 提炼适合的角色。
3. 判断使用单轮模板还是两阶段模板。
4. 写清 Problem Reducing 的拆解规则。
5. 写清 Sequentially Solve Subquestions 的上下文递进规则。
6. 写清是否展示过程，以及最终答案必须遵守的格式。
7. 输出完整 Prompt。

## 常见 Gotchas

- 子问题不是任务步骤清单，而是可以被回答的小问题。
- 拆解阶段不要把答案混进子问题列表。
- 子问题不能彼此独立散乱；要让后一个问题自然依赖前面的答案。
- 原始问题不要丢失；它应作为最终要回答的问题回到 Prompt 中。
- 对严格输出格式，过程可以内部完成，最终只输出目标格式。
