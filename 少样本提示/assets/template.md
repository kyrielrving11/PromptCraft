# 少样本提示案例

## 生成 Prompt 的原则

1. 角色扮演，在提示开头明确模型的角色和任务意图。

   示例：

   ```
   你是一名专业的信息抽取助手，负责按照示例中的格式从文本中抽取结构化信息。
   ```

2. 使用明确指令，将任务目标放在提示前部，并使用 `###` 或三引号 `"""` 分隔指令、示例和待处理文本。

   差例：

   ```
   Extract entities from the text.
   {text input here}
   ```

   优例：

   ```
   ### 任务
   从文本中抽取公司名称、人物名称、具体主题和总体主题。

   Text: """
   {text input here}
   """
   ```

3. 用户提供示例时，插入 1~5 组少样本示例。每个示例必须包含输入和期望输出，可选包含可公开的推理过程，用于展示任务模式、判断标准和格式风格。

4. 明确输出格式。少样本示例用于展示“怎么做”，输出要求用于约束“必须怎么输出”，两者都要保留。

5. 示例应来自用户在首次请求中附上的任务材料；不要把 `sample.md` 中的案例直接混入用户 Prompt。

6. 对代码任务，说明语言、函数名、输入输出、依赖限制，并在示例中展示最小可运行代码或期望 diff。

## 与零样本提示的区别

- 零样本提示只依赖角色、任务指令、上下文和输出格式。
- 少样本提示会额外加入用户提供的输入/输出示例，让模型模仿示例中的映射关系。
- 零样本中的“示例输出格式”只是格式骨架；少样本中的“示例”必须是完整的任务输入和期望输出。

## 纯 Skill 可选案例规则

1. 用户可以在首次请求中直接附上 1~5 组 `input/output` 或 `input/reasoning/output` 示例。
2. 若检测到示例，直接注入模板；不需要和用户二次交互。
3. 若未检测到示例，示例区写明“未检测到用户案例，因此按零样本提示生成”，并继续生成可用 Prompt。
4. 当 payload 设置 `persist_sample: true`，或调用脚本时使用 `--append-to-sample`，把本轮示例追加到 `assets/sample.md` 的“动态用户样例库”区。
5. 不要覆盖 `assets/sample.md`，因为它同时保存人工案例和用户明确要求沉淀的动态案例。

## Prompt 模板

<!-- PROMPT_TEMPLATE_START -->
{ROLE}
请根据任务说明、可选少样本示例和输出要求，为待处理内容生成符合要求的输出。

### 任务
{INSTRUCTION}

### 可选少样本示例
{FEW_SHOT_EXAMPLES}

### 输出要求
{OUTPUT_FORMAT}

### 待处理内容
"""
{TARGET_INPUT}
"""

### 约束
{CONSTRAINTS}

请只输出符合要求的结果，不要添加无关解释。
<!-- PROMPT_TEMPLATE_END -->

## 示例块格式

```markdown
#### 示例 1
输入：
"""
用户提供的示例输入
"""

推理过程：
"""
用户提供的可公开简要判断依据；没有时省略本块
"""

输出：
"""
用户提供的期望输出
"""
```

## 逐步生成方法

1. 读取任务描述、输出格式和可选用户示例。
2. 提炼任务角色和任务目标。
3. 有用户示例时，将示例格式化为输入/推理过程/输出对；没有推理过程时格式化为输入/输出对。
4. 没有用户示例时，在示例区说明按零样本提示生成，不要编造示例。
5. 写清输出格式、字段顺序、长度、语言和禁止项。
6. 使用三引号包裹待处理文本或占位符。
7. 输出完整 Prompt。

## 常见 Gotchas

- 示例和输出要求冲突时，以用户最新说明为准，并在 Prompt 中统一格式。
- 示例数量过多会挤占上下文，优先选择最能覆盖格式差异的 1~5 个。
- 示例只展示输出、不展示输入时，不符合少样本提示要求；不要编造输入，可忽略不完整示例并按零样本生成。
- 不要把一次性运行时示例误写进 `sample.md`；只有用户明确要求沉淀或 payload 设置 `persist_sample: true` 时，才追加到样例库。
- 推理过程应是可公开的简要依据，避免保存隐藏思维链、隐私、密钥或不可公开的内部分析。
